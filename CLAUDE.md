# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Расширение Chrome (Manifest V3), которое рисует копию встроенной панели закладок
внутри страницы, но в несколько строк. Сборка не требуется — исходники и есть то,
что грузится в браузер.

## Команды

```powershell
pwsh -File build.ps1        # dist\dbb-<version>.zip + печатает состав архива
```

`build.ps1` копирует только белый список путей (`manifest.json`, `_locales`,
`background`, `content`, `icons`, `newtab`, `options`, `popup`). Всё остальное —
README, `store/`, docs — в пакет не попадает. При добавлении новой папки с кодом
её нужно внести в `$include`, иначе она молча не уедет в магазин.

Тестового фреймворка и линтера нет. Синтаксис проверяется так (файлы — смесь ESM
и классических скриптов, поэтому копия с расширением `.mjs`):

```bash
cp content/content.js /tmp/c.mjs && node --check /tmp/c.mjs
```

Функциональная проверка — только вживую в браузере, см. «Отладка в Chrome».

## Архитектура

### Три контекста и почему между ними прокси

`chrome.bookmarks` недоступен контент-скрипту. Поэтому **все** операции с
закладками идут через service worker, который принимает только белый список
методов (`BOOKMARK_METHODS` в `background/service-worker.js`). Страница не может
через расширение сделать с закладками больше, чем делает сама панель. Добавляя
новую операцию, расширяйте этот список осознанно.

Протокол — один `chrome.runtime.onMessage` с таблицей `HANDLERS`:
`bookmarks` (прокси), `open` / `openAll`, `clipSet` / `clipGet` / `clipPaste`
(буфер вырезать-копировать-вставить, живёт в `storage.local`), `restore`
(отмена удаления), `openManager`, `openOptions`, `getSettings` / `setSettings` /
`resetSettings`, `activeTabInfo`.

### Два канала рассылки — оба обязательны

`chrome.tabs.sendMessage` доходит **только** до контент-скриптов.
`chrome.runtime.sendMessage` доходит до страниц расширения (новая вкладка, попап,
настройки), но не до контент-скриптов. Поэтому `scheduleBroadcast()` и
`broadcastSettings()` шлют в оба. Если забыть второй — панель на своей же
странице новой вкладки перестаёт видеть изменения закладок.

### Панель

`content/content.js` — один IIFE, ~1300 строк, вся панель целиком: отрисовка,
раскладка по строкам, меню, диалоги, drag & drop. Живёт в **закрытом** shadow
root внутри элемента `<dbb-bookmarks-bar>`, который вешается на
`document.documentElement` (не на `body` — тот у некоторых сайтов переписывается
целиком; на этот случай есть MutationObserver, возвращающий хост на место).

Хосту нельзя задавать `transform`, `filter`, `contain` или `will-change` — любое
из них создаёт containing block, и меню с `position: fixed` начнут
позиционироваться относительно панели, а не окна. Инлайновый стиль хоста
собирается в `hostCss()` и начинается с `all: initial !important`, чтобы правила
страницы вроде `* { margin: 0 }` до него не дотянулись.

### Переполнение строк — два режима

`relayout()` ведёт себя по-разному в зависимости от настройки `wheelScroll`:

- **включена** — `#rows` становится контейнером прокрутки, ничего не прячется,
  «»» показывает то, что сейчас вне видимой области (`updateOffscreen()`);
- **выключена** — элементы за последней строкой получают класс `.overflowed`
  и скрываются, «»» показывает именно их.

При переходе во второй режим обязателен `rowsEl.scrollTop = 0`: блок с
`overflow: hidden` сохраняет прокрутку, и замеры строк врут. У `#rows` намеренно
**нет** `overscroll-behavior: contain` — иначе колесо перестаёт передаваться
странице, когда панель дошла до края.

### Меню

`placeMenu()` держит правило: выпадающий список никогда не перекрывает кнопку,
которая его открыла. Высота ограничивается свободным местом под якорем, список
прокручивается, и только если снизу места меньше, чем сверху, — переворачивается
вверх. Подменю переворачивается влево у правого края экрана.

Любое изменение закладок перерисовывает панель целиком, что вырвало бы открытое
меню из-под курсора (заметно при перетаскивании внутри меню). Поэтому `refresh()`
запоминает цепочку открытых меню и позицию прокрутки (`captureMenuState()`)
и восстанавливает её после `render()` (`restoreMenuState()`).

### Страница новой вкладки

`newtab/newtab.html` подключает тот же `content/content.js` без изменений.
Связь между ними — два глобала в изолированном мире:

- `window.__dbbThemeOverride` — `newtab.js` выставляет `'dark'`, `applyTheme()`
  в контент-скрипте читает его вместо пользовательской темы;
- `window.__dbbRefreshTheme` — контент-скрипт публикует, `newtab.js` дёргает
  после смены настройки.

Порядок разрешения гонки: кто бы ни инициализировался первым, второй подхватит —
`newtab.js` вызывает `__dbbRefreshTheme?.()`, а `applyTheme()` читает override
каждый раз.

### Настройки

`background/settings.js` — единственный источник правды (`DEFAULTS`). Импортируется
попапом и страницей настроек напрямую, контент-скрипт получает разрешённую копию
сообщением. Новая настройка = ключ в `DEFAULTS` + поле в `options/options.html` +
имя в массиве `CHECKBOXES` / `SELECTS` / `RANGES` в `options/options.js` + строки
в обеих локалях.

## Чего делать нельзя

- **Сетевых запросов нет вообще.** Значки берутся из локального кеша браузера
  через `chrome-extension://<id>/_favicon/?pageUrl=…` (разрешение `favicon` плюс
  `_favicon/*` в `web_accessible_resources`). Это заявлено в описании магазина и
  в политике конфиденциальности — любой `fetch` наружу сломает и то и другое.
- **Никакого удалённого кода**, `eval`, `new Function`, `innerHTML`. В карточке
  магазина отмечено «удалённый код не используется».
- Разрешение `tabs` **не нужно**: `<all_urls>` и так открывает URL и заголовки
  вкладок. Оно было удалено намеренно, чтобы сократить поводы для ревью.

## Тонкости, на которых легко обжечься

- `chrome.bookmarks.move` внутри одной папки: индекс передаётся **как позиция в
  исходном списке**, Chromium сам вычитает единицу при движении вниз. Не надо
  корректировать вручную.
- Обе локали (`_locales/en`, `_locales/ru`) должны содержать одинаковый набор
  ключей; недостающий ключ не ломает сборку, а молча даёт пустую подпись.
  Интерфейс переключается по **языку браузера** (`chrome.i18n.getUILanguage()`),
  не по языку страницы и не по системе.
- Элементы с `hidden` требуют явного `[hidden] { display: none }` в `bar.css`,
  потому что `.item` задаёт `display: inline-flex` и перебивает стиль UA.
- Букмарклеты (`javascript:`) выполнить нельзя — MV3 это запрещает; расширение
  показывает об этом сообщение вместо тихого отказа.

## Соответствие нативной панели

Цвета и размеры не подбирались на глаз — они замерены попиксельно со скриншотов
встроенной панели (светлая и тёмная темы). Значения в `content/bar.css`. Меняя
палитру, сверяйтесь с нативной панелью тем же способом, а не «на вид».

Намеренные отличия перечислены в README в разделе «Насколько точно совпадает»:
кнопка «»» в крайнем правом положении, тёмный фон панели на две градации темнее
нативного, пустая страница новой вкладки. Их легко принять за баги — сверяйтесь
со списком, прежде чем «чинить».

## Отладка в Chrome

Загрузить распакованное расширение вручную: `chrome://extensions` → режим
разработчика → «Загрузить распакованное». После правок — «Обновить» на карточке
и перезагрузка страницы.

Автоматизация упирается в три ограничения, каждое из которых уже стоило времени:

1. `--load-extension` в свежих версиях Chrome игнорируется.
2. `--remote-debugging-port` не работает на профиле по умолчанию. Нужен отдельный
   `--user-data-dir`.
3. Загрузка через CDP `Extensions.loadUnpacked` требует флага
   `--enable-unsafe-extension-debugging`, **и** в `Default/Preferences` профиля
   должно стоять `extensions.ui.developer_mode: true` — иначе Chrome отключит
   расширение с причиной `DISABLE_UNSUPPORTED_DEVELOPER_EXTENSION`.

Shadow root закрытый, но DevTools его видит: `DOM.getDocument` с `pierce: true`
находит узел, `DOM.resolveNode` даёт objectId, дальше `Runtime.callFunctionOn`.
Так же проверяется drag & drop — синтетические события мыши через CDP настоящий
HTML5-перенос не запускают, приходится диспатчить `DragEvent` с собственным
`DataTransfer` прямо в shadow root.

## Публикация в магазин

`STORE.md` — статус готовности и чеклист. `store/listing.md` и
`store/fields/*.txt` — готовые тексты полей консоли разработчика.

- **Галерею расширений нельзя скриптовать расширением.** `chrome.google.com/webstore`
  и `chromewebstore.google.com` блокируют любой контент-скрипт, включая браузерную
  автоматизацию через расширение. Для работы с консолью разработчика нужен
  Playwright — на него ограничение не распространяется.
- Скриншоты и промо-плитка — **только 24-битный PNG без альфа-канала**.
- Скриншоты снимаются на синтетическом наборе закладок. Снимки с реального
  профиля в репозиторий и в магазин не попадают: они содержат личные ссылки.
  В `.gitignore` для этого есть правило на `docs/`.
